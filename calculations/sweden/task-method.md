# Метод расчёта человеческого минимума

## 1. Сначала результат, потом профессия

Мы не спрашиваем «нужны ли кассиры» или «нужны ли уборщицы». Мы спрашиваем:

- какой результат необходим;
- можно ли изменить организацию так, чтобы задача исчезла;
- можно ли выполнить её автоматизированной системой с требуемой надёжностью;
- где остаётся человеческое решение, физическое вмешательство или ответственность.

## 2. Классы задач

Каждая задача получает один из статусов:

- **A — исчезает:** результат не нужен или задачу можно убрать организацией;
- **B — автоматизируется:** результат нужен, но зрелая система может выполнять его без постоянного человека;
- **C — человек по исключениям:** обычный поток автоматизирован, человек нужен для аварий и нестандартных случаев;
- **D — человек необходим постоянно:** уход, сложное решение, физическая работа в непредсказуемой среде или персональная ответственность.

В S3 считается не число работников профессии, а часы для классов C и D плюс контрольная доля работы класса B.

## 3. Что нельзя автоматически исключать

Автоматизация кассы не устраняет доставку товара, контроль ошибок, возвраты и доступность магазина. Автоматизация уборки не устраняет санитарный результат, обслуживание машин и обработку нестандартных загрязнений. Поэтому строка удаляется из модели только после проверки полного процесса.

## 4. Формула

Для задачи `i`:

```text
hours_i = required_output_i × human_hours_per_unit_i × (1 - reliable_automation_i)
          + exception_hours_i
```

Затем добавляются обучение, отпуск, болезни, аварийный резерв и труд промежуточных поставщиков. Нельзя дважды добавлять один и тот же труд: либо считать цепочку через input-output таблицу, либо раскрывать её вручную.

## 5. Два предела

- **S3a:** исключаем только задачи, для которых автоматизация уже существует и может быть масштабирована в Швеции.
- **S3b:** дополнительно исключаем задачи, для которых есть инженерно правдоподобная, но ещё не массовая автоматизация.

Результат S3b не следует выдавать как прогноз ближайшего будущего. Это технологический предел при заданном уровне надёжности.
